### **Feature Overview**

The review agent was found to hallucinate file contents when making findings about files not included in a PR diff, resulting in false positive findings that erode trust in automated reviews. This change adds explicit cross-file verification instructions to the code-review skill (SKILL.md) and the correctness sub-agent definition, requiring the agent to read any file before asserting what it contains. These instruction files are embedded into the fullsend binary via Go's `embed.FS` and deployed to all enrolled repositories through the scaffold installation pipeline.

### **II. Software Test Plan (STP)**

This STP serves as the **overall roadmap for testing**, detailing the scope, approach, resources, and schedule.

#### **1. Scope of Testing**

Testing covers the correctness and completeness of cross-file verification instructions added to the code-review skill (SKILL.md) and the correctness sub-agent (correctness.md), as well as the scaffold embedding and deployment pipeline that delivers these files to enrolled repositories.

**Testing Goals**

- **P0:** Verify cross-file verification instructions are present and correctly worded in both modified skill files
- **P0:** Verify unreadable-file fallback language prevents false assertions
- **P1:** Verify scaffold embed includes updated files and they are deployable via the install pipeline
- **P1:** Verify self-check gate in step 4 requires file verification before recording findings

**Out of Scope (Testing Scope Exclusions)**

- [ ] **End-to-end agent behavior validation** — Verifying that the review agent actually follows the new instructions during live PR reviews requires production agent runs and is outside STP scope.
  - Rationale: Agent instruction-following is non-deterministic and cannot be reliably unit/functional tested.
- [ ] **Other false positive categories** — This fix targets cross-file content hallucination only; other false positive types are separate issues.
  - Rationale: Out of scope per GH-1835 which specifically addresses cross-file verification.
- [ ] **Upstream repository file access** — Testing whether the agent can read files in external repositories (e.g., konflux-ci repos).
  - Rationale: External repo access is a platform capability, not a feature under test.

#### **2. Test Strategy**

**Functional**

- [ ] **Functional Testing** — Validates that the feature works according to specified requirements and user stories
  - *Details:* Verify the cross-file verification instruction text is present in SKILL.md (steps 2 and 4) and correctness.md. Verify fallback and self-check language is correct.
- [ ] **Automation Testing** — Confirms test automation plan is in place for CI and regression coverage (all tests are expected to be automated)
  - *Details:* All tests are Go unit tests using the existing scaffold test infrastructure. Tests run in CI via `go test`.
- [ ] **Regression Testing** — Verifies that new changes do not break existing functionality
  - *Details:* Existing scaffold tests (TestWalkFullsendRepo, TestCollectInstallFiles_*) verify the embed and install pipeline. New content should not break existing tests.

**Non-Functional**

- [ ] **Performance Testing** — Validates feature performance meets requirements (latency, throughput, resource usage)
  - *Details:* Not applicable. Markdown content changes have no measurable performance impact.
- [ ] **Scale Testing** — Validates feature behavior under increased load and at production-like scale
  - *Details:* Not applicable. No runtime behavior changes.
- [ ] **Security Testing** — Verifies security requirements, RBAC, authentication, authorization, and vulnerability scanning
  - *Details:* Not applicable. No security-sensitive changes. The instructions improve review accuracy, which has indirect security benefits.
- [ ] **Usability Testing** — Validates user experience and accessibility requirements
  - *Details:* Not applicable. Changes are internal agent instructions, not user-facing UI.
- [ ] **Monitoring** — Does the feature require metrics and/or alerts?
  - *Details:* Not applicable. No new metrics or alerts needed.

**Integration & Compatibility**

- [ ] **Compatibility Testing** — Ensures feature works across supported platforms, versions, and configurations
  - *Details:* Not applicable. Markdown content is platform-independent.
- [ ] **Upgrade Testing** — Validates upgrade paths from previous versions, data migration, and configuration preservation
  - *Details:* Not applicable. No data migration or configuration changes.
- [ ] **Dependencies** — Blocked by deliverables from other components/products
  - *Details:* No external dependencies. The change is self-contained within the fullsend scaffold.
- [ ] **Cross Integrations** — Does the feature affect other features or require testing by other teams?
  - *Details:* The updated skill files affect all review agent runs across all enrolled repos. The pr-review skill dispatches the correctness sub-agent, which will pick up the new instructions.

**Infrastructure**
